## Rulings made on your behalf

Each is in the ledger with what it costs if wrong. The ones that changed the shipped result:

1. **Ran Task 2 before Task 1.** Task 1's module imports the ORM model at module level, so as
   written its whole test file would have failed to import. Task 2's stated dependency on Task 1
   was itself wrong — the model imports nothing from `app/core/`.
2. **A name-only `PATCH /users/{id}` recorded nothing** — my allowlist named three fields, two of
   which that route cannot change, and omitted `name`, which it can. Found by reading the diff, not
   by a reviewer. Fixed in `2b08c78`; `name` added to both user allowlists with a regression test.
3. **Three route paths in the plan were wrong.** Task 3 verified against the running app:
   clear-results is `POST /checklist-items/clear-results`; mock-data generation is
   `POST /checklist-modules/{id}/mock-data-generations`; the JSON export is `.../export.json`.
4. **Two of my own tests could never have passed.** Task 3's route walker missed FastAPI 0.141's
   router nesting and enumerated nothing; its exemption test used `isinstance(value, str)`, which is
   true for every `StrEnum` member. Both fixed; the guard now enumerates 65 real routes.
5. **Task 11's ask-route test** asserted `audit_rows() == []`, impossible once `conversation.created`
   exists. Rewritten to snapshot the count and assert it unchanged.
6. **Docs deferred to Task 16 deliberately** — `docs/data.md` and `CHANGELOG.md` land in one commit
   against the finished catalogue rather than being rewritten seven times. A reviewer flagged this
   as a gap; it is a decision. **If Task 16 does not deliver them, that is the defect.**
7. **`search` stays in `clear_results`' filter payload.** It is the caller's own query intent — a
   request parameter, not a fact about a repository — and it is what makes a bulk-destroy row
   actionable.
8. **Committed pre-existing `uv.lock` drift** (`4ea6c2a`) so later tasks got an unambiguous
   `git status`. The v2.0.0 release bumped `pyproject` without regenerating the lock.
